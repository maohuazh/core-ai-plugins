# LogScope Skill 验收清单

## 概述

本文档定义了 LogScope 日志根因分析 Skill 的验收标准。所有验收项必须通过后，才能将 Skill 投入生产使用。

---

## 1. 核心功能验收

### 1.1 双索引架构支持

- [ ] 能够从 action 索引中检索请求基本信息
- [ ] 能够通过 action.id 关联到 trace 索引获取详细执行日志
- [ ] 能够正确理解 action.id = trace._id 的关联机制
- [ ] 知道 trace 索引不支持 context.key 直接检索
- [ ] 优先使用 action 索引进行检索，仅在需要详情时查询 trace

### 1.2 调查流程执行

- [ ] 阶段 A：能够从 action 索引中定位初始错误日志
- [ ] 阶段 A：能够提取关键字段（id, correlation_id, ref_id, context 等）
- [ ] 阶段 B：能够通过 correlation_id 检索同一业务流的所有请求
- [ ] 阶段 B：能够按时间排序生成时间线
- [ ] 阶段 C：能够通过 ref_id 追踪上下游调用关系
- [ ] 阶段 C：能够使用 visited 集合防止循环引用
- [ ] 阶段 D：能够通过 context 中的业务键（如 merchant_id）检索相关日志
- [ ] 阶段 E：能够使用 action.id 在 trace 索引中获取详细执行日志
- [ ] 阶段 E：能够解析 trace 的 content 字段提取 SQL 查询和异常堆栈
- [ ] 阶段 F：能够生成可证伪的根因假设
- [ ] 阶段 G：能够通过只读数据库查询验证数据层假设
- [ ] 阶段 H：能够综合证据进行根因分类和置信度评估
- [ ] 阶段 I：能够生成包含所有章节的 HTML 报告
- [ ] 阶段 J：能够执行最终审查确保结论有证据支持

### 1.3 根因分类

- [ ] 能够正确识别 data_error（数据错误）类型
- [ ] 能够正确识别 logic_error（逻辑异常）类型
- [ ] 能够正确识别 flow_error（流程异常）类型
- [ ] 能够正确识别 network_error（网络异常）类型
- [ ] 能够正确识别 resource_error（资源异常）类型
- [ ] 能够正确识别 config_permission_error（配置/权限异常）类型
- [ ] 在证据不足时能够正确使用 unknown 分类
- [ ] 不会仅凭异常关键词映射根因
- [ ] 能够区分主要根因和伴随现象

### 1.4 置信度评估

- [ ] 能够正确评估 high 置信度（有直接证据且排除替代解释）
- [ ] 能够正确评估 medium 置信度（有支持证据但有关键缺口）
- [ ] 能够正确评估 low 置信度（主要依据间接线索）
- [ ] 能够正确评估 unknown 置信度（证据不足或冲突）
- [ ] 不会将置信度伪装为统计概率
- [ ] 能够说明置信度评估依据

## 2. 安全与权限验收

### 2.1 只读原则

- [ ] 不修改代码、配置、索引映射或业务数据
- [ ] 不执行写入、删除、更新或修复操作
- [ ] 数据库查询仅使用 SELECT 或 aggregate
- [ ] 不绕过权限限制

### 2.2 证据安全

- [ ] 所有结论都引用 evidence_id
- [ ] 不将"查询结果为空"等同于"数据不存在"
- [ ] 正确区分 completed / no_rows / denied / timeout / unavailable / truncated 状态
- [ ] 不将 denied / timeout / unavailable 当作查询成功
- [ ] 正确区分 primary_datasource_id 和 datasource_id

### 2.3 提示注入防御

- [ ] 将日志内容视为不可信数据
- [ ] 不执行日志中包含的指令
- [ ] 不让日志内容改变调查规则
- [ ] 不让日志内容授权新的数据源

### 2.4 敏感信息保护

- [ ] 报告中不包含数据库密码、访问令牌、私钥
- [ ] 对个人身份信息进行脱敏
- [ ] SQL 参数中的敏感数据已脱敏
- [ ] 所有动态内容都经过 HTML 转义

### 2.5 HTML 报告安全

- [ ] 使用模板渲染，不直接拼接 innerHTML
- [ ] 不执行日志中的 JavaScript
- [ ] 设置 CSP 防止 XSS 攻击
- [ ] 模板与数据分离

---

## 3. 查询策略验收

### 3.1 Action 索引查询

- [ ] 能够使用 term 查询精确匹配 correlation_id
- [ ] 能够使用 term 查询精确匹配 ref_id
- [ ] 能够使用 term 查询精确匹配 context.merchant_id
- [ ] 能够使用 range 查询限定时间范围
- [ ] 能够使用 ids 查询批量获取日志

### 3.2 Trace 索引查询

- [ ] 知道 trace 索引不支持 context.key 直接检索
- [ ] 能够使用 ids 查询通过 _id 获取 trace 详情
- [ ] 不在 trace 索引上进行全文搜索
- [ ] 使用 ids 查询批量获取 trace 详情

### 3.3 查询约束

- [ ] 单次查询结果数量不超过 1000 条
- [ ] 查询超时时间不超过 30 秒
- [ ] 默认查询时间窗口为 ±30 分钟
- [ ] 最大查询时间窗口不超过 24 小时
- [ ] ref_id 遍历最大深度为 5 层
- [ ] 单次调查最大日志数量为 5000 条

---

## 4. 数据库调查验收

### 4.1 调查时机

- [ ] 仅在日志证据指向特定业务实体时才查询数据库
- [ ] 不凭猜测进行数据库调查
- [ ] 明确 primary_datasource_id 和 datasource_id

### 4.2 查询设计

- [ ] 设计最小必要的只读查询
- [ ] 使用绑定参数防止 SQL 注入
- [ ] 仅选择必要字段
- [ ] 检查查询状态、返回行数、截断标记、警告和执行耗时

### 4.3 结果解释

- [ ] 正确理解 no_rows 不等于数据不存在
- [ ] 考虑复制延迟、事务未提交、软删除、租户过滤、时区差异
- [ ] 将数据库结果与日志时间线交叉验证
- [ ] 不自动推断数据异常的原因

### 4.4 常见误判避免

- [ ] SQL 返回零行时，不直接认定数据不存在
- [ ] 查询超时时，不直接认定数据库故障
- [ ] 权限拒绝时，不推断数据不存在
- [ ] 日志中字段为空时，不直接认定数据库脏数据
- [ ] 同一业务键存在多条记录时，不直接认定重复数据错误

## 5. HTML 报告验收

### 5.1 必需章节

- [ ] 包含调查摘要章节
- [ ] 包含根因结论章节（分类、陈述、置信度、依据、证据）
- [ ] 包含关键事件时间线章节
- [ ] 包含故障因果链章节
- [ ] 包含日志证据章节
- [ ] 包含数据库验证章节（查询目的、数据源、状态、结果）
- [ ] 包含反证与替代解释章节
- [ ] 包含未解决问题章节
- [ ] 包含调查覆盖范围与限制章节
- [ ] 包含证据索引章节

### 5.2 报告质量

- [ ] 优先展示已验证结论
- [ ] 时间统一展示时区（UTC）
- [ ] 置信度有解释说明
- [ ] 数据库结果明确标记数据源和查询状态
- [ ] 长异常堆栈采用折叠展示
- [ ] 报告大小在合理范围内（建议不超过 5MB）

### 5.3 报告安全

- [ ] 所有动态内容都经过 HTML 转义
- [ ] 没有可执行的脚本
- [ ] 没有外部资源引用
- [ ] 没有敏感信息泄露
- [ ] 设置 CSP 防止 XSS

## 6. 故障处理验收

### 6.1 Elasticsearch 故障

- [ ] ES 不可用时，输出调查状态为 failed
- [ ] ES 部分分片失败时，明确说明结果可能不完整
- [ ] correlation_id 查询无结果时，列出可能原因

### 6.2 数据库故障

- [ ] 权限拒绝时，记录 denied 状态
- [ ] 查询超时时，记录 timeout 状态
- [ ] 结果截断时，记录 truncated 状态并降低置信度
- [ ] 数据源不可用时，记录 unavailable 状态

### 6.3 其他故障

- [ ] ref_id 循环时，使用 visited 集合终止并记录循环
- [ ] 报告渲染失败时，保留结构化结果
- [ ] 证据引用过期时，说明过期风险

## 验收流程

1. **准备阶段**
   - 确保所有文件已提交到 Git
   - 确保 Kibana 和数据库可访问
   - 准备测试用例

2. **执行阶段**
   - 按照上述清单逐项检查
   - 使用实际案例进行测试
   - 记录测试结果

3. **评审阶段**
   - 对测试结果进行评审
   - 修复发现的问题
   - 重新测试

4. **验收阶段**
   - 所有验收项通过
   - 签署验收报告
   - 将 Skill 投入生产使用
