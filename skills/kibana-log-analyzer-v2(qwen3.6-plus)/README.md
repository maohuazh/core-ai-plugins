# Kibana日志分析Skill - 使用说明

## 快速开始

### 1. 安装Skill

Skill已安装在用户级目录: `~/.workbuddy/skills/kibana-log-analyzer/`

当你在对话中提到以下关键词时,系统会自动加载此Skill:
- "分析Kibana日志"
- "查看错误日志"
- "排查线上问题"
- "根因分析"
- "日志分析"
- "错误统计"
- "调用链分析"
- 以及其他相关表述

### 2. 使用示例

#### 示例1: 分析今天的错误日志
```
用户: 帮我分析一下今天的错误日志
```
AI将:
1. 查询最近1小时的ERROR级别日志
2. 按 app/action/error_code 分组统计
3. 为每个分组派发Sub Agent进行详细分析
4. 生成汇总报告和详细分析报告

#### 示例2: 分析特定服务的错误
```
用户: 看看payment-service最近2小时的错误
```
AI将:
- 只分析payment-service服务
- 时间范围调整为2小时
- 执行完整的分组分析和Sub Agent分析

#### 示例3: 分析特定调用链
```
用户: 这个correlation_id有问题: abc-123-def
```
AI将:
- 查询该correlation_id的完整调用链
- 分析调用链中的每个节点
- 定位失败点和根因

### 3. 前置要求

使用此Skill需要:
1. **Kibana URL**: 需要用户提供或配置环境变量 `KIBANA_URL`
2. **Python环境**: 系统需要安装Python 3.x
3. **curl命令**: Windows系统通常自带

### 5. 输出报告结构

最终会生成一份完整的Markdown报告,包含:

#### 总体概况
- 总错误日志数
- 错误分组数
- 涉及微服务数
- 各等级问题数量

#### 错误分布
- 按微服务维度统计
- 按错误类型维度统计

#### 详细分析
每个错误分组的完整分析:
- Trace日志详情
- 调用链分析
- 根因分析(不是表面现象)
- 影响评估(范围+等级)
- 修复建议(紧急/优化/架构/监控)

#### 优先级排序
按P0/P1/P2/P3排序的问题列表

#### 修复计划
- 紧急修复 (Today)
- 短期优化 (This Week)
- 长期改进 (This Month)

### 6. 自定义配置

#### 修改分析时间范围
默认分析最近1小时,可以在对话中指定:
```
用户: 分析最近3小时的错误日志
```

#### 修改分析日期
默认分析当天,可以指定历史日期:
```
用户: 分析2026.04.17的错误日志
```

#### 过滤特定服务
```
用户: 只看order-service和user-service的错误
```

### 7. 核心规则

Skill严格遵守以下规则:
- ✅ 必须分组分析(不逐条分析)
- ✅ 必须派发Sub Agent(每组一个,并行执行)
- ✅ 必须结合trace日志和源码
- ✅ 必须深入根因(不只看表面)
- ✅ 必须生成完整报告
- ❌ 禁止修改任何代码
- ❌ 禁止跳过分析步骤
- ❌ 禁止串行执行Sub Agent

### 8. 技术架构

#### 查询脚本
`scripts/query_logs.py` - 核心查询脚本
- 支持分组统计模式
- 支持trace详情查询
- 支持调用链查询
- 自动处理curl命令

#### 参考文档
- `references/log-structure.md` - 日志字段说明、索引结构、常见错误模式
- `references/sub-agent-guide.md` - Sub Agent分析指南,确保分析质量

### 9. 故障排查

#### 问题: 无法连接Kibana
**解决**: 确认KIBANA_URL环境变量正确配置,或直接在对话中提供URL

#### 问题: Python命令不可用
**解决**: 安装Python 3.x,或指定可用的Python命令路径

#### 问题: 查询返回空结果
**解决**: 
- 确认日期格式正确(yyyy.mm.dd)
- 确认索引存在(action-yyyy.mm.dd, trace-yyyy.mm.dd)
- 尝试扩大时间范围
