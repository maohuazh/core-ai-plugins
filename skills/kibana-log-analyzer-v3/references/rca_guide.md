# 根因分析（Root Cause Analysis）指南

## 分析框架

### 1. 错误分类

根据错误特征将问题分为以下几类：

#### 1.1 代码缺陷类
- 空指针异常（NullPointerException）
- 数组越界（IndexOutOfBoundsException）
- 类型转换错误（ClassCastException）
- 逻辑错误（条件判断、循环边界等）

#### 1.2 资源类
- 数据库连接池耗尽
- 内存溢出（OOM）
- 文件描述符耗尽
- 线程池满

#### 1.3 外部依赖类
- 第三方 API 超时/不可用
- 数据库慢查询/死锁
- 消息队列积压
- 缓存服务异常

#### 1.4 配置类
- 环境变量缺失/错误
- 超时配置不合理
- 线程池/连接池配置不当
- 路由/网关配置错误

### 2. 分析步骤

#### Step 1: 错误堆栈分析
1. 定位异常堆栈的顶层异常（Root Exception）
2. 识别异常发生的代码路径（类名、方法名、行号）
3. 分析异常传播链路

#### Step 2: 上下文分析
1. 检查 `context.*` 字段中的业务参数
2. 分析输入数据是否异常
3. 检查调用链中的上下游服务状态

#### Step 3: 源码对照
1. 根据堆栈中的类名和方法名定位源码
2. 分析出错代码的业务逻辑
3. 检查是否有边界条件处理缺失
4. 检查异常处理是否完善

#### Step 4: 影响范围评估
1. 统计错误日志的出现频率
2. 分析影响的用户/订单/业务量
3. 评估对下游服务的影响

### 3. 根因判定标准

一个有效的根因分析必须回答：
- **What**: 发生了什么错误？
- **Where**: 错误发生在哪个服务、哪个代码位置？
- **Why**: 为什么会发生这个错误？（直接原因 + 根本原因）
- **Impact**: 影响了多少用户/请求？影响等级如何？
- **How to fix**: 如何修复？（短期修复 + 长期优化）

### 4. 影响等级评估

| 等级 | 标准 | 响应要求 |
|------|------|----------|
| P0 - 致命 | 核心功能不可用，影响 >50% 用户 | 立即响应，30 分钟内修复 |
| P1 - 严重 | 核心功能异常，影响 10-50% 用户 | 1 小时内响应，4 小时内修复 |
| P2 - 一般 | 非核心功能异常，影响 <10% 用户 | 4 小时内响应，24 小时内修复 |
| P3 - 轻微 | 边缘功能异常，影响极小 | 下一个迭代修复 |

### 5. 常见 Java 异常根因模式

#### NullPointerException
- **直接原因**: 对象未初始化或返回 null
- **根本原因**: 缺少空值检查、外部服务返回异常、数据库查询无结果
- **修复方案**: 增加空值判断、使用 Optional、完善异常处理

#### TimeoutException
- **直接原因**: 外部服务响应超时
- **根本原因**: 网络问题、下游服务性能下降、超时配置不合理
- **修复方案**: 优化超时配置、增加重试机制、降级处理

#### SQLException
- **直接原因**: 数据库操作失败
- **根本原因**: SQL 语法错误、连接池耗尽、死锁、慢查询
- **修复方案**: 优化 SQL、调整连接池、增加索引、分库分表
